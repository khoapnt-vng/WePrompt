## 2. Exact foundation boundary

`PRESENTATION_RUN_V2_ENABLED` remains `false` throughout this plan.

| Surface                                                 | Flag true in a test/dev build                             | Flag false    |
| ------------------------------------------------------- | --------------------------------------------------------- | ------------- |
| Selected PPTX, supported individual AionRS conversation | Managed v2                                                | Existing path |
| Selected PPTX, supported individual ACP conversation    | Managed v2                                                | Existing path |
| Selected PPTX, Guid first send                          | Create draft and conversation, bind once, then managed v2 | Existing path |
| Team-owned conversation                                 | Reject managed start                                      | Existing path |
| Unknown conversation ownership                          | `SCOPE_UNAVAILABLE`; reject managed start                 | Existing path |
| No selected template                                    | Existing path                                             | Existing path |
| Selected DOCX or HTML template                          | Existing path                                             | Existing path |
| Project Home composer                                   | Existing path                                             | Existing path |
| Browser/WebUI upload                                    | Not supported in this slice                               | Existing path |

The only renderer-callable operations permitted while the flag is false are `get`, `listRecoverable`, `openRecovery`, and safety-qualified `discard` for runs that already exist. False-flag source draft/grant, `start`, dispatch claim/renew, new dispatch, and new inspection reject before lookup, filesystem access, locking, rate mutation, dialog display, or backend access.

One narrow internal exception prevents loss of truth after the flag flips: an already persisted `dispatching` or `bound` run may record its backend acknowledgement, exact conversation/turn association, terminal evidence, uncertainty, retention, and tombstone. That reconciliation cannot initiate another POST, extraction, inspection, render, or publication. Add RED tests for flag-off after POST invocation and after binding.

Main enforces the flag, desktop runtime, and scope twice:

1. the native IPC provider rejects before dispatching to a service; and
2. `PresentationRunService.start` rejects direct/internal calls before side effects.

The renderer-local `getPresentationRunEligibility` helper added in Task 4 is a UX hint only. It grants no authority.

The foundation lifecycle is split into two durable state dimensions.

Dispatch journal:

```text
allocating -> committed -> dispatching -> bound -> terminal_verified -> retained
     |            |             |           |                    |
     |            |             |           |                    +-> failed_retained
     |            |             |           +-> dispatch_uncertain
     |            |             +-> dispatch_uncertain
     |            +-> failed_retained
     +-> failed_retained

allocating | committed -> discarded only while POST has not begun
bound -> retained only for safe retention with TRACKING_REQUIRED, no candidate, and no inspection authority
retained | failed_retained -> discarded
dispatch_uncertain -> no destructive transition in this foundation
```

Artifact phase:

```text
none
  -> sources_snapshotted
  -> sources_extracted
  -> candidate_retained
  -> candidate_copied
  -> structurally_valid
  -> ooxml_inspected
  -> rendered_exact_hash
```

`TRACKING_REQUIRED` and `REVIEW_REQUIRED` are dispositions, not dispatch or artifact states. `terminal_verified` means main proved the exact terminal event and released runtime; only then may main authorize the pure inspector. Do not collapse dispatch status, artifact phase, and disposition. Do not introduce an `interrupted` state that implies a backend POST is safely retryable.

type DispatchInitialPresentationRunRequest = {
  conversation_id: string;
  run_id: string;
  lease_token: string;

All request schemas are strict and reject unknown fields. IDs are nonempty bounded UUIDs, revisions are nonnegative safe integers, `relative_path` is a bounded normalized relative path, picker filters are main-owned, and external drop accepts 1–16 actual Electron-backed `File` objects. Lease tokens are opaque, single-run capabilities and the only secret returned; no result includes source/native/template/workspace/candidate/evidence paths, directive text, backend body, turn payload, port, or token.

The hidden external-drop IPC accepts preload-derived native paths but is not present in `ipcBridge`, native provider constants, or renderer types. Renderer can call only the `electronAPI.presentationSources.grantExternalDrop` signature above.

Only `RATE_LIMITED` and `BACKEND_PREFLIGHT_BLOCKED` have `retryable: true`, and both prove `postInvoked: false`. Every other code is statically `retryable: false`. In particular, `DISPATCH_UNCERTAIN` requires `state: 'dispatch_uncertain'` and `details: { runId, postInvoked: true, queryRequired: true }`. Task 1 must add an exhaustive `satisfies Record<PresentationRunFailureCode, ...>` policy fixture plus strict Zod cases proving no code can appear with another retryability/state/details shape.

Recovery ordering is `updatedAt DESC, runId DESC`. `limit` defaults to 20 and is restricted to 1–20. `nextCursor` is an authenticated, opaque, main-minted encoding of the conversation ID and final sort tuple; structurally valid but unauthenticated, malformed, cross-conversation, or no-longer-resolvable cursors return `INVALID_REQUEST`. The resolved tuple must belong to that same conversation. The user-facing recovery list includes exactly `retained`, `failed_retained`, and `dispatch_uncertain`; it excludes `allocating`, `committed`, `dispatching`, `bound`, `terminal_verified`, and `discarded`. Separate internal scans return `dispatching | bound` for socket/terminal reconciliation and `terminal_verified` for incomplete retained-candidate/readiness work; `committed` belongs to initial-dispatch recovery, not this list. `get` by a known authorized run or client request remains available for every live state and retained tombstone. List returns no more than 20 entries and no raw state/path. The same request always returns a stable discriminant; raw exceptions, backend strings, and filesystem errors never cross IPC.

The union above is the allowed-combination table. In particular, `dispatch_uncertain` can only be `TRACKING_REQUIRED` with no retained candidate or action; a retained candidate can appear only after `terminal_verified` and `candidate_retained`; Open is authorized only at `ooxml_inspected` or `rendered_exact_hash` with persisted safety evidence bound to the exact durable hash and length, and the Open operation repeats those checks; earlier candidate phases allow Discard but never Open; and `discarded` clears artifact/disposition/candidate from the public DTO. Tests must reject every impossible combination at compile time and runtime.

### 3.4 Grant creation flows

Main owns these exact flows:

- **Prompt-only:** `sources: []`; no grant is created.
- **Existing conversation/native picker:** renderer calls `pickSources({ conversation_id })`; main opens the dialog, validates and snapshots the chosen files, and returns descriptors.
- **Existing conversation/workspace source:** renderer calls `grantWorkspaceSource({ conversation_id, relative_path })`. The path must be relative. Main resolves the authoritative conversation workspace and proves containment before reading.
- **Electron external drop:** a dedicated managed-v2 preload method accepts real Electron `File` objects, obtains their private paths with existing `webUtils.getPathForFile(file)`, and sends those paths directly to the narrow main grant handler. That method returns descriptors only.
- **Guid:** create a main-owned source draft, grant picker/drop sources into that draft, create the conversation, call `bindDraft` exactly once, and only then call `start`.

Browser/WebUI uploads and synthetic/pasted `File` objects are explicitly unsupported. `/api/fs/upload` returns an absolute server path, so it cannot be reused as a renderer-safe capability. Pre-conversation workspace-relative grants are also deferred.

An existing raw/ungranted attachment blocks a managed send with a localized “reselect sources” action. It sends nothing and preserves the pending submission and selected template.

### 3.5 Main grant record and limits

Each unbound snapshot lives under `app.getPath('userData')/presentation-source-grants/<grant-uuid>/`, with a mode-`0700` directory, atomic manifest, and mode-`0600` source file. The main record owns only the snapshot-relative name and state `active | claimed | consumed | revoked | expired`. `start` claims all grants atomically under sorted owner/grant locks. A replayed, foreign-owner, expired, revoked, consumed, hash-mismatched, size-mismatched, or missing grant fails closed. A claim becomes consumed only when the run is durably bound; claimed snapshots move into run accounting and inherit run retention.

Grant policy:

- supported formats: PDF, DOCX, XLSX, PPTX, TXT, MD, CSV;
- an empty Guid draft is `active` for exactly 15 minutes from `createdAt`; at the boundary, startup or five-minute GC atomically transitions it to `expired`, writes a seven-day draft tombstone, removes only its owned empty directory, and releases the live-draft slot;
- replaying `createDraft` with the same client request ID or calling `bindDraft` during that tombstone returns `DRAFT_EXPIRED`; after tombstone expiry it returns `DRAFT_NOT_FOUND`, while a new client request ID may allocate a new draft;
- empty and source-bearing unbound drafts share the app cap of 16; the 17th returns non-retryable `DRAFT_LIMIT_EXCEEDED`, and an expired draft counts as reclaimed only after the atomic expiry transition;
- maximum 16 sources, 64 MiB per source, and 256 MiB total;
- validate extension plus magic/container structure;
- stream the source exactly once into a new mode-`0600` snapshot;
- `fstat` before and after streaming, hash the bytes while copying, and reject identity/size drift;
- atomically persist the manifest only after the snapshot is durable;
- every active, unqueued picker/drop/workspace/Guid grant expires 15 minutes after creation or last successful reselect;
- a confirmed queued item may extend its still-unclaimed grants once to a 24-hour queue expiry; enqueue failure leaves the 15-minute expiry;
- maximum 16 active/unbound grants and 256 MiB per owner (conversation or Guid draft);
- maximum 64 active/unbound grants, 16 live Guid drafts, and 512 MiB of unbound grant snapshots per app;
- claimed/consumed grants leave unbound counts immediately but remain covered by run count/byte limits;
- startup GC plus a five-minute sweep atomically tombstones expired/revoked grants before deleting only their owned UUID directory;
- keep grant and draft tombstones seven days to reject replay; and
- quota checks and claims run under sorted owner/grant/draft locks.

`PresentationSourceGrantService` itself—not only IPC—must verify flag true, desktop runtime, and authoritative owner before lock acquisition, dialog display, source lookup, file read, directory creation, rate/quota mutation, or manifest write. Direct service calls receive the same fail-closed result.

Reuse `callAuthorizedOfficeArtifact` for authoritative conversation lookup and `resolveOfficeArtifactPath`, `hashOfficeArtifact`, and `ArtifactScratchService` where their contracts match. Do not fork weaker path checks.

## 4. Durable store and dispatch contract

The base has no mutex suitable for this run. Add a main-process keyed lock for request, run, conversation, turn, grant, and draft keys. Acquire multi-key sets in sorted order. Allocation, grant claim, bind, terminal reconciliation, and discard are exclusive.

The canonical manifest is authoritative and carries a monotonic `revision`. Every mutation is compare-and-swap:

1. append and `fsync` a write intent;
2. write the next manifest to a same-directory temp file and `fsync` it;
3. atomic rename and directory `fsync`;
4. append and `fsync` the commit record; and
5. update derived indexes after the canonical commit.

Conversation, request, turn, and grant indexes are derived and repairable; they never authorize an action. Startup scans canonical manifests, reconciles incomplete intents, quarantines corrupt records, and rebuilds indexes. Tests inject a crash at every manifest, journal, and index boundary.

Use an injected `syncDirectory` durability boundary. The POSIX adapter opens the directory read-only, calls `FileHandle.sync()`, and closes it. Directory-sync errors are persistence failures and are never swallowed as successful durability. Until a verified Windows directory-flush adapter exists, managed v2 remains unenableable on Windows; Windows behavior is tested through the injected boundary while the feature stays disabled by default. Fsync the parent after UUID-directory creation, quarantine rename, tombstoned deletion, and any other durable directory-entry change.

The canonical run stores a normalized request fingerprint and, after allocation, any exact public failure envelope produced by local preparation. Repeating the same `client_request_id` plus the same fingerprint returns the same durable success or failure discriminant. Reusing that ID with a different fingerprint returns `REQUEST_COLLISION`; it never degrades into `RUN_STATE_CONFLICT` or re-executes preparation.

`start` claims grants, allocates the durable initial-send record, and reaches `committed` without network activity. For a queued item, the renderer does not call `start` until the item is durably claimed at the queue head; for an immediate item, it first records the pending submission. Renderer then uses an opaque revision/CAS lease through `claimInitialDispatch`, `renewInitialDispatch`, and `dispatch`. Only the main lifecycle coordinator can act on that lease. It:

1. perform all local preflight checks while `committed`;
2. persist `dispatching`;
3. issue one backend POST through the existing main-capable local HTTP bridge;
4. persist the acknowledged conversation/turn tuple; and
5. transition to `bound`.

The backend has no idempotency key. Once POST invocation begins, timeout, connection loss, cancellation, crash, missing acknowledgement, HTTP 409, and every other 4xx/5xx transition to `dispatch_uncertain`. Never automatically retry, requeue, or repost. The existing busy classifier inspects error text and is not proof that a POST was not accepted.

Only a transient local preflight rejection before step 2 may remain `committed` and retryable, and only with durable proof that POST invocation never began. A hard local preflight failure becomes `failed_retained`. If the backend acknowledged but persistence of the binding cannot be proven, the result is uncertain. If binding persisted but the IPC reply was lost, the renderer queries `get` by stable request/run ID and never posts again.

Binding is idempotent for the exact same run/conversation/turn tuple and rejects a conflicting turn. Dispatch tombstones are retained seven days.

## 5. Main terminal ownership and initial-send leases

Renderer terminal events cannot authorize `finish`. Remove renderer-facing finish authority.

The current `ipcBridge.conversation.turnCompleted` path is renderer-only because `httpBridge.ensureWs()` does not open a WebSocket when `window` is absent. Add a main-global backend event client using the existing `ws` package and the local backend token in its query string. Initialize it exactly once in `packages/desktop/src/index.ts` after `markBackendReady`/`exposeBackendPort` makes the port and token authoritative. Test reconnect, duplicate events, malformed events, token handling, and restart reconciliation.

The client accepts at most a 256 KiB inbound frame and uses a per-connection token bucket of 120 events/minute with burst 20. It holds at most 32 terminal-before-bind tuples, one per exact conversation/turn, for 120 seconds. It has zero reconnect-message buffer. Oversize, flood, pending overflow, or malformed input quarantines the stream, performs no run transition, closes/reconnects with bounded backoff, and leaves affected runs tracking-required. Diagnostics are rate-limited to one entry per error code per 60 seconds and never include payload bodies, bearer/query tokens, or the token-bearing WebSocket URL.

Do not reuse the permissive renderer mapper as main evidence: it defaults missing status/runtime fields. `PresentationRuntimeEventClient` must strictly parse raw events with exact conversation ID, turn ID, and terminal status; runtime is nullable evidence. The event is only a trigger. Before gating, main must prove the durable run/conversation/turn association and confirm the associated runtime is released.

Only a strict matching terminal event plus released runtime may reach `terminal_verified`. After restart without that event, two released-runtime observations at least 30 seconds apart may only establish safe retention with `TRACKING_REQUIRED`/unknown; they never authorize inspection. Missing, mismatched, stale, or forged evidence fails closed.

Managed initial sends use the durable main manifest created by `start`, never renderer `sessionStorage` as authority:

- stable `client_request_id` and `run_id`;
- 30-second dispatch claim lease;
- renewal every 10 seconds while the owning renderer request is alive;
- remount may claim `committed` only after lease expiry; and
- `dispatching`, `bound`, and `dispatch_uncertain` are observe-only.

This corrects managed ACP removal-before-send and AionRS marker behavior without changing legacy initial-message keys. A background retry is allowed only for a durable `committed` record with proof POST was never invoked. It is prohibited for `dispatching`, `bound`, `terminal_verified`, and `dispatch_uncertain`.

## 6. Queue, draft, scope, and containment rules

### 6.1 Queue schema version 2

A managed queued item stores raw input, `PresentationSourceRef[]`, selected template ID, stable client request ID, and execution state. It stores no path. `enqueue`, `update`, `claimHead`, and `remove` must await a confirmed durable write and readback. Quota/storage/write failure sends nothing and retains the pending submission, grants, and selected template.

Allocation occurs only after a durable `queued -> claimed` transition at the queue head; enqueue never creates a run. Keep the item through `start`, lease, and dispatch, and delete it only after main reports `bound`. A pre-dispatch transient block may return to queued. Any post-attempt uncertainty becomes a paused, non-sendable tracking item and is never retried or requeued.

The submitted snapshot is separate from the editable new draft. The shared `SendBox` currently clears input before awaited `onSend`; managed flow must instead move the submitted snapshot into pending state while allowing new typing independently. A pre-dispatch failure offers explicit **Restore** and never overwrites newer text. Only confirmed `bound` or confirmed queued persistence clears the pending snapshot.

On the current backend, idle observations cannot prove a POST was rejected or that no late writer exists. Therefore `dispatch_uncertain` has no Open, Discard, GC, retention-expiry, or pressure-delete transition in this foundation. It remains indefinitely and blocks new starts under byte/count pressure. At 30 days emit a bounded operator alert only. Destructive cleanup requires a future authoritative backend request/turn negative-correlation contract.

Read-only Open is separate from cleanup safety: it is available only for a durable candidate copied after `terminal_verified`. An uncertain run never reaches that copy step, so it has no openable candidate.

### 6.2 Team exclusion

The main conversation DTO has no trusted team marker. Inject a main-owned scope resolver based on authoritative `TTeam.assistants[].conversation_id` data. A renderer `isTeamSend` boolean and the legacy database are not authority. If main cannot enumerate owner-to-team membership reliably, return `SCOPE_UNAVAILABLE` and keep the feature unenableable until BUG-013 declares an authoritative source.

Supported runtime values are exactly `aionrs` and `acp`. Direct IPC attempts against a team or unknown-scope conversation must reject.

### 6.3 Honest containment

The agent/tool runtime can still write elsewhere in the conversation workspace. This foundation does not claim OS sandboxing and a prompt directive is not a security boundary. Its narrow guarantee is: **no WePrompt-published or authorized managed workspace deliverable**.

The immutable base also exposes legacy raw paths through `electronAPI.getPathForFile` and existing renderer path-bearing attachment sends. Managed-v2 request/result/dispatch DTOs do not use those paths, but their global existence prevents a compromised-renderer containment claim. This foundation does not migrate unrelated workspace, knowledge-base, or legacy attachment consumers.

Flag enablement therefore requires both an independently verified tool write allow-list/sandbox for the managed invocation and retirement or gating of legacy renderer raw-path capabilities from any renderer that can invoke managed v2. Until both pass, keep the flag false even if deterministic tests pass. User copy must say “candidate” and “review required,” never “cleaned,” “ready,” or “delivered.” Retain the exact candidate and hash-bound evidence for authorized Open or Discard.

## 7. Extraction, OfficeCLI, readiness, and fixed limits

### 7.1 Deterministic extraction

- PDF: existing PDF.js extractor only; at most 50 pages. No OCR/model fallback.
- DOCX: OfficeCLI text view, then Mammoth fallback.
- PPTX: OfficeCLI text view, then `officeparser` fallback.
- XLSX: existing SheetJS conversion. Do not invent an OfficeCLI XLSX schema.
- TXT/MD/CSV: bounded strict UTF-8.

OfficeCLI `1.0.143` was observed on the immutable checkout:

- PPTX text JSON normalizes from `{ success: true, data: { totalSlides, slides: [{ index, path, texts: string[] }] } }`.
- DOCX text JSON normalizes from `{ success: true, data: { totalElements, elements: [{ path, type, text }] } }`.

Implement per-format object normalizers. Do not require `data` to be a string and do not heuristically accept raw stdout. Preserve the existing 8 MiB `maxBuffer`. Fixture tests must use the observed tracked `business-review.pptx` and `business-report.docx` output shapes.

### 7.2 Durable grants and three run-owned file areas

Before a run, source bytes exist only in the durable grant root defined in Section 3.4. For run `<uuid>`:

1. agent staging under `app.getPath('temp')/aionui-presentation-runs/<uuid>/agent/` contains only `candidate.pptx`, model-facing `grounding.md`, and `plan.json`;
2. authoritative state under `app.getPath('userData')/presentation-runs/<uuid>/` contains the manifest, claimed grant snapshots, hashes, facts, journals, indexes, and—only after terminal proof—`retained/candidate.pptx`; and
3. private inspection under `app.getPath('temp')/aionui-presentation-inspection/<uuid>/<inspection-uuid>/` contains an exclusive stable candidate copy and renders.

Evidence, retained-candidate, and inspection paths never appear in managed-v2 DTOs or model instructions. A v1 scratch marker has no v2 authority. Recovery and Open resolve only `retained/candidate.pptx` from the canonical manifest; agent staging is never a recovery source.

### 7.3 Readiness contract

Only after `terminal_verified`, open and `fstat` the exact staging candidate, hash it, copy it with exclusive creation to a same-directory temporary file under `retained/`, set mode `0600`, `fsync`, hash the retained temp, re-hash staging, then atomically rename and directory-`fsync`. A manifest CAS records `candidate_retained`, relative retained name, byte length, and hash. A crash before that CAS leaves no authorized candidate; startup removes an unreferenced temp or reconciles an exact committed intent.

Task 6 creates a separate exclusive inspection copy from the durable retained candidate, never from staging. Reject symlink/nonregular/hardlink/path drift, and require:

```text
staging hash before retain
  == retained temp hash
  == staging hash after retain
  == manifest retained hash
  == inspection copy hash
  == retained hash after structural validation
  == retained hash after OOXML inspection
  == retained hash after every slide render
```

Any mismatch fails closed and preserves only the last canonical state. Inspection files/renders are removed after durable evidence. Discard deletes staging, retained run state, and claimed grant children only by canonical UUID ownership; it never accepts a caller path.

Validate `plan.json` with exactly one entry per slide and at most 16 known `sourceRefs` per slide. Slide-level provenance does not prove semantic truth.

Mechanical blockers include structural failure, stale/missing evidence, invalid plan, unresolved refs, literal escape tokens, unresolved placeholders, required-notes failure, selected-template content slides with no non-text visual anchor, malformed/unsafe OOXML, missing/oversized render, or any hash drift.

Covers, dividers, quotes, closings, and minimal slides may be exempt only under bounded role, position, and shape rules. Do not claim to mechanically score typography, composition, narrative quality, or truth.
