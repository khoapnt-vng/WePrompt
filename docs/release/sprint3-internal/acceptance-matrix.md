# Sprint 3 Packaged Acceptance Matrix

This matrix applies only to the held, unsigned internal packages for Windows x64 and macOS ARM64. Run Windows first. Do not begin macOS acceptance until all four Windows entry gates pass. A blank, skipped, inferred, or source-only result is not a pass.

Use a clean machine or reverted snapshot for each platform. Record the exact package identity, tester environment, UTC start and end times, status, bounded notes, and hashed packet-relative evidence in `evidence-index.json`. For any `fail` or `blocked` result, preserve the failing fixture and record its controlled location, hash, reason, and owner. Never include credentials, authentication headers, user-home paths, or unsanitized customer data.

## Windows entry gates

| ID                                | Required observation                                                                                                                                                                  | Evidence                                                                      | Fail condition                                                                          |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| `W01_NATIVE_SOURCE`               | The exact held WePrompt RC completes its required source gates on a native Windows x64 runner.                                                                                        | Sanitized logs bound to the WePrompt commit and Windows environment.          | Missing native run, wrong commit, failed gate, or incomplete log.                       |
| `W02_BUG043_FILESYSTEM`           | BUG-043 filesystem/readiness checks pass on NTFS with the packaged Windows AionCore binary.                                                                                           | Filesystem identity, readiness output, and log hash.                          | Readiness was not exercised on NTFS or reports an unexpected path/state.                |
| `W03_BUG043_PACKAGED_FAIL_CLOSED` | Removing, denying, or corrupting the packaged AionCore dependency produces the documented fail-closed state without silently continuing. Restore the package before scenario testing. | Sanitized failure output plus a hashed controlled fixture record.             | Silent fallback, destructive mutation, ambiguous success, or missing preserved fixture. |
| `W04_INSTALLED_BUNDLE`            | The installed application uses the AionCore binary and bundle manifest whose hashes match `artifact-index.json`.                                                                      | Installed paths expressed packet-relatively, plus binary and manifest hashes. | Missing component or any identity/hash mismatch.                                        |

All four gates must be `pass`. A Windows gate failure stops packaged acceptance and forces `decisionReadiness: not_ready`.

## Cross-platform scenarios

Run all scenarios in order on Windows x64, then repeat them in order on macOS ARM64. Every scenario requires direct observation from the installed package.

| ID                           | Setup and assertion                                                                                                                                                                                     | Required evidence                                                                              | Fail or block condition                                                                                         |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `S01_INSTALL`                | Verify the package SHA-256, follow the unsigned-install steps, launch, and confirm the expected internal build identity.                                                                                | Package hash, install log or screenshots, displayed build identity.                            | Hash mismatch, unexpected signing claim, install/launch failure, or wrong identity.                             |
| `S02_SPRINT2_MIGRATION`      | Start from a controlled Sprint 2 data fixture and open Sprint 3. Confirm migration completes without data loss and the lineage fingerprint matches the held artifact.                                   | Before/after fixture hashes, migration log, lineage fingerprint, representative record counts. | Destructive change, lost records, unexpected migration, or lineage mismatch.                                    |
| `S03_LINEAGE_FAIL_CLOSED`    | Present an incompatible or tampered lineage fixture. Confirm startup refuses unsafe migration and preserves the fixture.                                                                                | Sanitized failure output and preserved fixture hash/location.                                  | Application continues, mutates the fixture, or presents an ambiguous success state.                             |
| `S04_HTTP_WS_AUTH`           | Exercise authenticated HTTP and WebSocket access, then repeat with missing/invalid authorization. Valid access succeeds and invalid access is denied without exposing credentials.                      | Sanitized request outcomes and server logs with all sensitive values removed.                  | Unauthorized access succeeds, valid access fails, or evidence contains sensitive material.                      |
| `S05_MCP_OAUTH_TOOL`         | Complete the supported MCP OAuth flow and invoke a representative tool through the installed application.                                                                                               | Sanitized consent/callback states and tool result.                                             | OAuth cannot complete, tool invocation fails, or credentials appear in evidence.                                |
| `S06_OAUTH_EXPIRY`           | Expire or revoke the controlled OAuth grant. | `S11_STUDIO_ABSENT`          | Confirm Creative Studio routes, navigation, commands, and runtime entry points are absent or fail closed in the package.                                                                                | UI/route/command observations and configuration evidence.                                      | Any reachable Creative Studio surface or enabled runtime path.                                                  |
| `S12_UPDATE_ABSENT`          | Confirm auto-update, update feed publication, and Sentry release upload are absent/disabled; the package remains manual-install only.                                                                   | Configuration and observed UI/network behavior, sanitized as needed.                           | Update prompt/feed traffic, automatic replacement, or Sentry release behavior.                                  |

## Result rules

- `pass` means the required packaged behavior was directly observed and hashed evidence is present.
- `fail` means the observed behavior violated the assertion. Preserve the fixture; do not erase the result with a later attempt.
- `blocked` means the assertion could not be completed for a recorded reason. The only unresolved block permitted in a decision-ready packet is `S09_BUG017` while runtime recovery remains explicitly unbuilt.
- Any rerun is a new retained evidence record outside this index; never overwrite the underlying evidence for an earlier result.
