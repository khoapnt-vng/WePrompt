The two no-action rows are the load-bearing part. Offering “Open Model settings” for a health flip or a catalog fault sends the user to a screen that cannot help them, and dresses a system fault as their problem.

updateSelection refuses while another write is in flight, so the sibling trigger disables for the duration. There is no Apply button, so there is never a partial-success state to model — two independent atomic writes, each with its own revision guard, and the renderer never shows an optimistic value. Three distinct failures, three sentences: a generic refusal; “Your unsaved changes could not be saved, so the engine was not set”; and a stale project, which must not reuse the existing copy about someone else changing it.

Still open

Four questions the drawing cannot settle. The first is blocking.

German at the narrowest width

Each slot carries a model name, a four-part capability summary and sometimes a full sentence, and German runs about 30% longer. These are blocking, spend-relevant facts, so truncation is not permissible — the strip must wrap to a second and sometimes third line, in a panel whose scarce axis is height. Someone has to draw the wrapped state before this is built.

Does “Coherence: on” earn a permanent line?

Kept here because the chain needs a name and this is the only place it gets one. A designer may reasonably rule that a healthy-state sentence is noise and only the off states should speak. Copy exists for both.

Does the Brief mount survive Table / Board / Cut?

It is one of three and nothing depends on it. Dropping it costs the zero-scene onboarding moment. Decide once the new shell is real.

The Director will plan against dead bounds

The route catalog is a frozen snapshot handed to the Director when its server starts. Making engine switching easy and in-place increases how often it proposes 12-second clips to a 4–8s engine. A notice is a weak remedy; the real fix is a refreshable snapshot, outside this surface. This design creates that cost rather than inheriting it.
